## Context

Newsflash is a Vite 8 + React 19 SPA with no PWA metadata. The current `index.html` has a basic `<meta name="viewport">`, a theme-setting script, and an SVG favicon. There is no web app manifest, no multi-size icon set, and no Apple-specific meta tags. The app already supports dark/light/system themes via a `dark` class on `<html>`, with the theme preference stored in localStorage under `newsflash:theme`.

## Goals / Non-Goals

**Goals:**

- Make Newsflash recognizable as a PWA to browsers and operating systems
- Provide a complete icon set that looks sharp on all devices and contexts (home screen, app switcher, splash screen, taskbar)
- Support Apple devices with appropriate meta tags and touch icons
- Respect the existing dark/light theme with appropriate `theme-color` values
- Design a simple, memorable icon that conveys "news" at small sizes

**Non-Goals:**

- Service worker registration — that's Step 2
- Install prompt UX — that's Step 4
- Generating platform-specific splash screen images (Apple splash screens are derived from the icon + background color by the OS)
- Animated icons or platform-specific icon variants beyond maskable

## Decisions

### Manifest in `public/manifest.json` as a static file

The manifest will be a static JSON file in `public/` rather than being generated by `vite-plugin-pwa` (which is added in Step 2). This keeps Step 1 independent and simple. When Step 2 adds `vite-plugin-pwa`, it can either reference this file or inline the manifest — either way, the static file serves as the source of truth during Step 1.

Alternative considered: waiting until Step 2 to add the manifest via `vite-plugin-pwa`'s `manifest` option. Rejected because the manifest and icons are a standalone concern that should be testable independently.

### Icon design: stylized lightning bolt on a solid background

The icon uses a bold lightning bolt (⚡) on a solid brand-colored background. The lightning bolt conveys speed and "flash" (from "Newsflash") and is recognizable even at 48x48. The background color is a vibrant blue (`#2563eb` — Tailwind `blue-600`) which provides good contrast and visibility on both light and dark home screens.

Alternative considered: a newspaper/document icon. Rejected because it's generic and doesn't connect to the "Newsflash" brand. Also considered a combination mark (bolt + text) but text is illegible at small icon sizes.

### Maskable icon with safe zone padding

Android adaptive icons crop the icon to various shapes (circle, squircle, etc.). The maskable variant places the lightning bolt within the safe zone (inner 80% circle) with the brand background filling the full canvas. This prevents the bolt from being clipped on devices that use circular icons.

Alternative considered: using a single icon for both `any` and `maskable` purposes. Rejected because the safe zone padding would make the `any` purpose icon look too small with excessive padding.

### Theme-color meta tags with media queries

Two `<meta name="theme-color">` tags will be added: one for light mode (`#ffffff`) and one for dark mode (`#0a0a0a`, matching the existing dark background). The `media` attribute on each tag ensures the browser address bar matches the app's theme without JavaScript intervention.

Alternative considered: a single brand-colored theme-color (`#2563eb`). Rejected because it would clash with the app's white/dark backgrounds and look jarring when switching between the browser and the app.

### SVG favicon retained, PNG fallback added

Modern browsers support SVG favicons and the current `favicon.svg` works well. A 32x32 PNG fallback is added for older browsers. The SVG will be updated to match the new icon design (lightning bolt).

## Risks / Trade-offs

**[Trade-off] Static manifest requires manual sync with vite-plugin-pwa in Step 2** → When Step 2 is implemented, the plugin's manifest config must match or reference `public/manifest.json`. This is a minor coordination cost that keeps Step 1 self-contained.

**[Risk] Icon design may not match user's brand vision** → The lightning bolt is a reasonable default. The icon files are simple PNGs that can be regenerated easily if the user wants a different design.

**[Trade-off] No splash screen images** → iOS and Android generate splash screens from the manifest's `background_color` + icon. Custom splash screen images would provide a more polished experience but add significant maintenance burden (many device sizes). Deferred to a future enhancement if needed.
